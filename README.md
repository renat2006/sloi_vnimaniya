# Слои внимания

Интерактивный перформанс о стратиграфии внимания. Колба на экране наполняется
песком, пока страница удерживает фокус. Каждый уход оставляет слой другой
породы. В конце сеанса стекло исчезает, и у зрителя на руках керн — срез,
который читается как порода.

## Как запустить

```bash
node server.js
```

Откройте http://localhost:4173. Сборки нет: статические файлы и нативные
ES-модули. Сервер добавляет только зал присутствия; без него всё работает,
кроме живого зала — запустить можно и `python3 -m http.server 4173`.

Для показа на аудиторию: запустите сервер на своей машине и дайте остальным
адрес вида `http://<ваш-ip>:4173` — все, кто откроет его, окажутся в одном зале.

## Как это развёрнуто

Работа живёт на `https://sloi.renat.site`. На сервере:

- `/opt/sloi` — файлы приложения;
- `sloi.service` — systemd-юнит, держит `node server.js` на `127.0.0.1:4173`;
- `/var/lib/sloi/sloi.db` — база (каталог выдаётся юниту через `StateDirectory`,
  сам `/opt/sloi` смонтирован только на чтение);
- `/etc/caddy/apps.d/sloi.renat.site.caddy` — Caddy проксирует домен на этот
  порт с `flush_interval -1`: без этого поток зала присутствия буферизуется и
  колбы других перестают обновляться. TLS Caddy получает и продлевает сам.

Выкатить изменения:

```bash
SLOI_HOST=user@host SLOI_KEY=~/.ssh/key.pem ./deploy.sh
```

Скрипт синхронизирует файлы и перезапускает сервис. Адрес и ключ можно
положить в `.deploy.env` рядом — он не попадает в репозиторий.

## Публикация на GitHub Pages

Settings → Pages → Deploy from a branch → `main` / `/ (root)`. Через минуту
работа будет жить по адресу `https://<логин>.github.io/<репозиторий>/`.

Сборки нет, путей от корня нет, файлов с подчёркиванием нет — статика уезжает
как есть. На Pages работает всё: сеанс, круг разрешённого, песок, керн, архив,
неделя, обмен кернами по ссылке, экспорт PNG.

**Кроме живого зала.** Pages отдаёт только файлы и не запускает Node, поэтому
зал присутствия там выключится сам: страница честно напишет «локальный режим»,
галочка «войти в зал» откажется включаться, всё остальное продолжит работать.

### Если живой зал нужен и на Pages

1. Положите `server.js` на любой хост, умеющий Node — Render, Railway, Fly,
   Glitch. Зависимостей нет, порт берётся из `PORT`, слушает `0.0.0.0`.
2. Впишите адрес в `js/config.js`:

   ```js
   const RELAY = 'https://ваш-зал.onrender.com';
   ```

3. Адрес обязан быть `https://` — страница на Pages отдаётся по https и до
   `http://` не достучится (mixed content).

Проверить чужой зал, ничего не правя, можно параметром:
`…/?relay=https://ваш-зал.onrender.com`.

Для показа в аудитории проще без всякого хостинга: `node server.js` на своей
машине и адрес `http://<ваш-ip>:4173` остальным — все окажутся в одном зале.

## Установка на телефон

Работа собрана как PWA: ставится с домашнего экрана, запускается без
браузерной обвязки и открывается офлайн.

- **iPhone** — откройте `https://sloi.renat.site` в Safari, «Поделиться» →
  «На экран „Домой“».
- **Android** — Chrome сам предложит установку, либо меню → «Установить
  приложение». В самой работе на экспликации появится строка «Установить
  на телефон».

Что даёт установка:

- полноэкранный режим — колба занимает весь экран, браузерных панелей нет;
- офлайн — оболочка и весь код лежат в кэше, сеанс можно провести без сети
  (живой зал при этом недоступен, работа честно уходит в локальный режим);
- ярлыки долгого нажатия по иконке: «Начать сеанс» и «Архив кернов».

**Экран не гаснет.** На телефоне сон экрана — это `visibilitychange`, то есть
разрыв. Поэтому сеанс удерживает экран через Wake Lock: телефон лежит на
столе, колба наполняется, а вы работаете на бумаге или за ноутбуком. Если
система откажет в удержании, работа об этом скажет вслух.

Нативной обёртки нет намеренно: она потребовала бы Xcode, подписи и стора,
не дав ничего сверх того, что уже умеет установленная PWA.

## Три породы

| Слой | Что это |
| --- | --- |
| тёплый, золотой | непрерывный фокус на странице |
| каменный, серо-зелёный | переход внутри круга разрешённого |
| холодный, синий | разрыв: вкладка, окно, уведомление |

Браузер не знает, в какое приложение вы ушли, и узнать не может. Поэтому
порода определяется не слежкой, а показанием: вернувшись, вы отвечаете, где
были, и слой меняет состав. Прибор здесь — человек, со всей известной
погрешностью самоотчёта.

## Психология, на которой всё держится

- **Обет перед началом.** Задача + круг разрешённого + формула «если… — то…».
  Намерения-исполнения повышают доводимость (Gollwitzer, 1999); добровольное
  ограничение работает лучше навязанного (Ariely & Wertenbroch, 2002).
- **Дымка возвращения.** Первые ~70 секунд после разрыва рисуются с примесью
  холодного: остаточное внимание (Leroy, 2009). После каменного перехода
  дымка вдвое слабее — уместное переключение тоже стоит времени
  (Monsell, 2003), но меньше.
- **Метка рекорда.** Пунктир в колбе — ваш длиннейший непрерывный отрезок.
  Усилие растёт у самой цели (Hull, 1932; Kivetz et al., 2006).
- **Разрыв — не приговор.** Слой после разрыва подан как новая точка отсчёта
  (Dai, Milkman & Riis, 2014), а не как провал.
- **Зал без рейтинга.** Присутствие других меняет исполнение (Triplett, 1898;
  Zajonc, 1965), но публичное сравнение подтягивает отстающих и расслабляет
  опережающих (Schultz et al., 2007). Поэтому в зале видно присутствие и
  состояние — и никакого ранжирования.

## Социальный слой

**Зал присутствия.** Колбы всех, кто вошёл, стоят рядом и наполняются в реальном
времени. Передаются только имя, доля заполнения, состояние и число слоёв — ни
задачи, ни истории. Вход добровольный и по умолчанию выключен.

**Эксперимент.** Каждый керн помечен: был ли сеанс одиноким. Архив сам считает
среднюю глубину фокуса наедине и при свидетелях — зритель ставит опыт на себе.
Выборка мала и не рандомизирована; это наблюдение, и так и подписано.

**Обмен образцами.** Керн умещается в строку (~140 символов). Ссылкой можно
поделиться: чужой срез встанет в ваше собрание, а все керны собрания
складываются в коллективный.

## Как устроена живая часть

Три слоя, каждый отвечает за своё.

**Горячее состояние — в памяти процесса.** Кто сейчас в зале, насколько полна
его колба, в фокусе он или в разрыве. Это живёт секунды и не должно касаться
диска: участник, замолчавший на 12 секунд, считается ушедшим.

**Долгое хранение — SQLite** (`node:sqlite`, встроен в Node 22+, ни одной
зависимости). Две таблицы: `cores` — керны, извлечённые при свидетелях, и
`events` — журнал зала. База лежит вне каталога приложения, в
`/var/lib/sloi/sloi.db`, в режиме WAL: чтения не блокируют записи.

**Канал — Server-Sent Events.** У каждого события зала есть порядковый номер.
Браузер при обрыве сам переподключается и присылает `Last-Event-ID`, сервер
доливает только пропущенное. Поэтому ничего не теряется и ничего не надо
перезагружать руками: вкладка может пролежать в фоне, потерять сеть, вернуться —
и догонит ленту с того места, где оборвалась.

### Почему не WebSocket и не брокер

**WebSocket** нужен, когда клиент шлёт поток данных серверу. Здесь наоборот:
вниз — непрерывно, вверх — короткий сигнал раз в три секунды. SSE это делает
поверх обычного HTTP, с переподключением и докачкой из коробки, проходит через
любой прокси и не требует ни библиотеки, ни отдельного протокола.

**Брокер сообщений** (Redis, RabbitMQ, Kafka) решает задачу доставки событий
между несколькими процессами. Здесь процесс один: события расходятся по
подписчикам напрямую, за микросекунды. Брокер добавил бы демон, второй сетевой
прыжок и новый способ всё сломать — ради нуля выигрыша. Он понадобится ровно
тогда, когда сервер перестанет помещаться в один процесс; в этот момент
`logEvent` и `pushPeers` станут публикацией в канал, а остальной код не
изменится.

**Кеш** уже есть и стоит там, где нужен: горячее состояние зала в памяти,
а на диск уходит только то, что должно пережить перезапуск.

## Сеанс не теряется

Пока колба наполняется, состояние сеанса пишется в `localStorage` — при каждой
смене слоя и раз в четыре секунды. Если вкладку закрыли, перезагрузили или
телефон выгрузил страницу из памяти, при следующем заходе сеанс поднимается с
того же места. Время отсутствия не замалчивается: оно честно ложится в колбу
разрывом, и приложение об этом сообщает. Если за время отсутствия колба
переполнилась, керн извлекается сам и уходит в архив.

## Звук: три слоя

Звук собран из трёх слоёв, и каждый отвечает за своё. Песок — вещество,
музыка — смысл, события — разметка.

### Слой 1. Песок

Не ровный шум, а **отдельные зёрна**: короткие всплески через резонансный
фильтр, до тридцати в секунду, каждое со своим тембром и местом в
стереополе. Поверх них ровная подложка и низкий «корпус» сосуда.

Главное здесь — **резонанс растёт по мере наполнения**, с 520 Гц у пустой
колбы до 2300 Гц у полной. Ровно так меняется звук, когда наливаешь воду
в бутылку: воздушный столб укорачивается, и тон ползёт вверх. Уровень
слышно, не глядя, и это не метафора, а физика сосуда.

Каждая **видимая** упавшая песчинка щёлкает в звуке отдельно и чуть
громче фоновых зёрен: что видно, то и слышно. При доливе после отсутствия
песок идёт лавиной, а музыка пригибается — возвращённое время слышно как
физическое событие.

**Выход и возврат** сделаны крупными жестами. На разрыве бас вздувается
почти вдвое, фильтр песка обваливается с рабочего резонанса до 420 Гц за
девять десятых секунды, россыпь зёрен уходит вниз по частоте, и всё это
накрывает чистый синусовый спад с 330 до 74 Гц. Возврат — зеркальный
жест: зёрна поднимаются вверх, фильтр открывается, звучит тёплый
синусовый тон на 396 Гц.

### Слой 3. Тишина

Звук привязан к жизненному циклу. Партитура идёт только во время сеанса:
на завершении разрешается и через семь секунд гасит все голоса точно в
ноль. Уход со страницы сеанса останавливает её, уход из архива или зала
останавливает озвучивание керна, а скрытая вкладка глушится за пару
секунд, чтобы ничего не играло в кармане.

### Слой 2. Музыка

Во время наполнения играет музыка — настоящая, с гармонией и мелодией, а
не звуковой фон. Её устройство выведено из того, что известно о звуке и
сосредоточенной работе, и у неё есть три назначения.

**Три назначения.**

1. **Маскировка.** Самый разрушительный звук вокруг — разборчивая чужая
   речь: она бьёт по вербальной рабочей памяти сильнее любого шума
   (Salamé & Baddeley, 1982). Непрерывный музыкальный слой накрывает её.
2. **Разметка времени.** Гармонический круг из четырёх аккордов по
   шестнадцать секунд даёт времени форму: вы чувствуете, сколько прошло,
   не глядя на колбу.
3. **Обратная связь.** Музыка отражает состояние — по ней слышно, что
   происходит с вниманием.

**Чего в ней нет и почему.** Слов и пения — см. выше. Ударного ритма и
развития: мешает не громкость, а непредсказуемая смена событий
(гипотеза меняющегося состояния, Jones, Madden & Miles, 1992). Поэтому
круг повторяется, переходы между аккордами идут плавным глиссандо за
две секунды, а мелодия строго внутри текущего созвучия — сюрпризов нет
по построению. Бинауральных ритмов нет намеренно: их доказательная база
противоречива.

**Что есть.**

- **Неподвижный бас** на 55 Гц и над ним круг из четырёх созвучий:
  открытое, минорное, подвешенное, светлое. Тоника не меняется весь
  сеанс — опора; меняется только цвет над ней.
- **Дыхание.** Громкость всего слоя колышется с частотой 0,1 Гц — шесть
  раз в минуту. Это резонансная частота дыхания, с которой связывают
  парасимпатическую активацию; музыка тихо предлагает такой ритм.
- **Мелодия** — редкие колокольные ноты из тонов текущего созвучия,
  раз в 4–10 секунд. Чем полнее колба, тем плотнее ноты и выше регистр:
  это слышимый градиент цели (Hull, 1932; Kivetz et al., 2006).
- **Глубина слышна.** По мере наполнения вступают верхние голоса: в
  начале звучит только бас, к концу — всё созвучие.

**Как музыка отражает состояние.**

| Что происходит | Что делает музыка |
| --- | --- |
| фокус | круг идёт, мелодия звучит |
| разрыв | круг **замирает** на текущем аккорде, строй разводит на четверть тона, фильтр темнеет, мелодия умолкает |
| возвращение | круг идёт снова, но мелодия возвращается не сразу: сначала тишина, потом редкие ноты, потом полностью |
| ответ «был в круге» | мелодия и строй возвращаются втрое быстрее |
| колба полна | добавляется терция, которой не было весь сеанс, и низкий колокол |

Замирание круга — главный ход. Уходя, вы не выключаете музыку, вы
**останавливаете время в ней**; вернувшись, слышите, что она вас ждала.
А возвращение мелодии ступенями — это остаточное внимание на слух: вы
уже здесь, но музыка ещё не вся здесь. Финальная терция звучит потому,
что память об эпизоде держится на пике и на конце (Kahneman et al., 1993).

## Керн можно послушать

Готовый керн озвучивается за 12–28 секунд — кнопка есть и на этикетке, и
на карточке в архиве. Керн читается снизу вверх, как его читал бы геолог:
высота тона растёт с глубиной залегания слоя, длительность фразы
пропорциональна длительности слоя, а порода слышна в составе созвучия —
тёплый слой консонансом, каменный с лёгкой расстройкой, разрыв резким
расстроенным тембром. Границы слоёв отмечены ударом.

Это сонификация в прямом смысле (Hermann, Hunt & Neuhoff): те же данные,
поданные другому чувству. Получасовой сеанс становится двадцатисекундной
пьесой, и дроблёный день слышно раньше, чем видно.

## Устройство

| Файл | Назначение |
| --- | --- |
| `js/geom.js` | профиль колбы, объём → высота, морфинг колба ⇄ керн |
| `js/paint.js` | отрисовка страт: три породы, дымка, зерно, контакты |
| `js/stage.js` | сцена: зал, луч света, стекло, струя, отражение, керн |
| `js/session.js` | модель сеанса, склейка микроразрывов, метрики |
| `js/store.js` | локальный архив, круг, рекорд, кодирование керна |
| `js/archive.js` | собрание, неделя, коллективный керн, экспорт PNG |
| `js/net.js` | клиент зала: поток событий, присутствие, публикация кернов |
| `js/audio.js` | три слоя звука и озвучивание готового керна |
| `js/config.js` | адрес зала присутствия (пусто — тот же origin) |
| `sw.js` | сервис-воркер: оболочка в кэше, зал и керны всегда из сети |
| `manifest.webmanifest` | описание приложения для установки на телефон |
| `server.js` | статика, зал присутствия, SQLite и журнал событий — без зависимостей |

Индекс дробления = 1 − Σ(fᵢ/F)², где fᵢ — длительности непрерывных рабочих
отрезков (фокус и круг вместе). Монолит даёт 0, крошево — близко к 1.
Разрывы короче 350 мс не считаются: это шум переключения раскладки.

Архив живёт в `localStorage`. Наружу уходит только то, что вы сами отправили,
войдя в зал или поделившись ссылкой.

## Android-приложение

Папка `android-app/` — оболочка на Capacitor: тот же сайт (`https://sloi.renat.site`) в нативном окне плюс возможности, которых нет у PWA:

- **Виджет** трёх размеров (адаптируется при изменении размера): колба, нарисованная настоящими слоями сеанса и последнего керна, живой таймер и остаток, серия дней и минуты за сегодня, кнопки быстрого старта «15 / 25 / 50 мин» и «Завершить». Цвета и радиусы скруглений подстраиваются под систему (Android 12+), в списке виджетов — генерируемое превью (Android 15+).
- **Live Update** — уведомление «сеанс идёт» с обратным отсчётом и сегментированным прогрессом по слоям; на Android 16 оно становится чипом в статус-баре и виджетом на экране блокировки, на старых версиях — обычное постоянное уведомление. По окончании — отдельный сигнал точным будильником (`AlarmManager`), даже если приложение закрыто.
- **Плитка быстрых настроек** и **ярлыки** на иконке (начать 25 минут, зал, архив), монохромная иконка для тем Android 13+.
- **Системная хаптика** (`performHapticFeedback` и примитивы `VibrationEffect`), нативное удержание экрана, Predictive Back (в сеансе «Назад» сворачивает приложение, а не закрывает).
- **App Links**: ссылки на керны `https://sloi.renat.site/#s=…` и корень сайта открываются прямо в приложении (`/.well-known/assetlinks.json` с отпечатком релизного ключа).

Виджет, ярлыки и плитка открывают приложение по ссылкам вида `?go=start&min=25`, `?go=finish`, `?go=stage`; ту же схему понимает и сайт.

Веб-код узнаёт о нативной оболочке через `js/native.js`; в браузере и PWA этот модуль ничего не делает. Виджет получает состояние через плагин `SloiBridge` (`android-app/android/app/src/main/java/site/renat/sloi/`).

Сборка (нужны Android Studio с SDK и JDK 21):

```bash
cd android-app
npm install
export JAVA_HOME=/opt/homebrew/opt/openjdk@21/libexec/openjdk.jdk/Contents/Home
npm run apk        # android/app/build/outputs/apk/debug/app-debug.apk
npm run sync:dev   # версия, которая смотрит на локальный сервер: http://10.0.2.2:4173 (эмулятор)
```

Публикация в Google Play потребует подписанного `release`-билда (keystore) и аккаунта разработчика. Разрешение `USE_EXACT_ALARM` разрешено политикой Play для приложений-таймеров.

## Релизы и CI

`.github/workflows/ci.yml` — на каждый пуш и pull request: проверка синтаксиса, смоук-тест сервера (`ci/smoke-web.mjs`: статика, закрытые файлы, протокол зала, push) и debug-сборка Android.

`.github/workflows/release.yml` — релиз по тегу:

```bash
git tag v1.2.0 && git push origin v1.2.0
```

Workflow соберёт подписанные `APK` (universal: один файл для ARM64, ARMv7, x86, x86_64) и `AAB` для Google Play, проверит подпись, посчитает `SHA256SUMS.txt`, запустит приложение на эмуляторах Android 9, 12 и 14 и опубликует релиз со статусом, описанием и списком изменений. Версия берётся из тега: `v1.2.0` → `versionName 1.2.0`, `versionCode 1002000`; тег с суффиксом (`v1.3.0-beta.1`) выходит как пре-релиз.

Один раз перед первым релизом нужно положить ключ подписи в секреты репозитория (ключ создан локально в `~/.sloi-signing/`, храните его копию):

```bash
bash ci/set-secrets.sh   # ANDROID_KEYSTORE_BASE64, ANDROID_KEYSTORE_PASSWORD, ANDROID_KEY_ALIAS, ANDROID_KEY_PASSWORD
```

Страница загрузки — `/download/` (`download/index.html`): сама подтягивает список версий из GitHub Releases, показывает актуальную сборку, историю, описания и отпечаток сертификата. После выхода релиза её не нужно обновлять.
